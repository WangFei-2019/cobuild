# 共建 · CoBuild

一个围绕「目标、分工、进展、交付与验收」的小团队项目协作应用。使用 React 19 与 Ant Design 6，提供独立项目空间、成员跨项目视图和可核对的计划调整流程。

本仓库以 **Node.js 正式协作服务**为实际使用方式：真实账号、邀请、权限与服务器持久化。GitHub Pages 提供工作区连接入口；本地演示独立保留在 `demo.html`。

[正式工作区](https://123.57.227.212:5175/) · [GitHub 入口](https://wangfei-2019.github.io/cobuild/) · [独立演示](https://wangfei-2019.github.io/cobuild/demo.html#/dashboard) · [产品与设计依据](设计依据.md)

| --- | --- | --- |
| 项目、成员、任务、里程碑、成果交接 | 当前浏览器内操作并保存 | 服务端保存，按账号权限共享 |
| 工作台与搜索 | 示例人员的跨项目工作 | 当前真实账号的可见工作 |
| 登录与邀请 | 明确标注的本地体验，无真实邀请 | 自助注册、真实账号、项目邀请、访问控制 |
| 项目体检与简报 | 根据当前记录运行可解释规则，简报可编辑、复制和下载 | 同样支持，分析范围遵循当前项目访问权限 |

| 数据位置 | 浏览器 localStorage | 服务器持久化目录 |

## 产品能力

- **我的工作台**：个人待办按项目分组，切换我推进、待我验收、需协助与全部相关待办；每条任务带实际项目色边与项目名标签，列表、表格和手机一致；项目范围、期限筛选和任务数量一致，跨项目搜索独立呈现可访问结果。
- **个人设置与工作区管理**：个人资料、账号安全、AI 服务分别位于 `/account/profile`、`/account/security`、`/account/ai`，旧 `/account` 入口仍可用；成员可管理自己的资料、密码和个人模型，平台部署与额度管理仅管理员可见。邮箱验证与找回密码使用平台统一邮件服务，支持 QQ SMTP 与 Resend 兼容接口。普通使用者无需配置发件邮箱。
- **站内提醒**：从当前可见项目整理待处理事项，保存每个账号的已读状态，并可直接进入相关任务。
- **项目归档**：项目管理者可归档真实项目，在项目中心恢复；保留任务、成员和成果，归档期间不进入日常待办与搜索。
- **独立项目空间**：项目说明、目标、任务列表与看板、成员、里程碑、成果、动态和设置各自有明确入口。
- **自选项目颜色**：创建与项目设置都支持预设、调色板和 HEX 色值，项目导航与来源标记同步更新。
- **人员与项目成员分开管理**：人员目录添加与编辑姓名、简介、颜色；职责与访问角色按项目设置。完整服务可生成邀请链接，由已有账号或新注册人员确认加入；Pages 只管理本地档案，不生成真实邀请。
- **统一成员档案**：按项目颜色查看一个人参与的项目、分工、进度与成果，区分本人提交和旧记录按任务归属。
- **成员交接与退出**：查看未结束的推进和验收责任，选择承接人后退出、移除或降为只读；支持转交项目管理权，保留至少一位已关联账号的有效管理员。离开后的身份和已验收成果仍可追溯，旧邀请不能恢复已撤销权限。
- **任务取消与恢复**：管理者说明原因后取消未完成任务，历史、文件和依赖保留；取消从有效任务完成率、日常待办和提醒中移出。恢复时重新核对分工与期限，不会把取消当作完成。
- **围绕任务讨论**：有效协作者和接收人均可发表讨论、回复、提及伙伴或提出待确认问题，作者及管理者可标记问题已解决。讨论不改变任务进展或交付约定。
- **交付闭环**：明确负责人、接收人、前置任务和验收要求，提交成果、退回修改、重新交付及确认；阶段验收依据实际任务交接。
- **可检查的规划**：载入明确标注的示例草案，修改里程碑、分工、日期与依赖；调整剩余工作时先看前后对比，再确认，保留已有成果和验收记录。
- **报告导出**：导出项目、里程碑及验收记录、任务日期和依赖、受阻项、成果版本与最近动态。
- **项目副驾**：查看每一条风险的记录依据和建议动作，分开呈现完整交接、完成标记、期限和依赖；编辑一份五段式简报草稿，再复制或下载。
- **外部 AI 方案往返**：在副驾填写要求，预览并复制规划提示词，在自己选择的 AI 中生成结构化方案，再导入共建。项目、原始版本、模式、成员、日期、依赖和受保护成果均要校验，确认前不会更新项目。

所有演示人物与项目均为合成示例。修改只影响当前浏览器；清除站点数据或重置演示会移除本地改动。演示版不包含 API Key，不代发邀请，不提供真实账号认证或跨设备同步，也不会把预置规划称为真实 AI 输出。

副驾的体检与简报是本地规则整理，不能证明成果质量，也不预测工时或完成日期。外部 AI 流程由用户主动复制资料，应用不会替用户发送；请先核对提示词预览。导入格式为 `cobuild-plan-exchange-v1` 信封，包含 `projectId`、`baseRevision`、`mode` 和 `draft`；返回方案必须保留这些元信息。项目在 AI 处理期间变化时，需要重新导出最新上下文。简报文字支持本账号、本浏览器的 7 天草稿；复制或下载可另外留档。

## 日常效率与 AI 协作

- **恢复草稿**：任务、进展、成果文字和链接、讨论、初始/剩余规划、简报与 AI 工具输入按账号、项目和表单隔离，保存在当前浏览器 7 天。恢复只填入输入，仍需核对当前版本与权限；密码、模型 Key、邀请令牌及文件二进制不进入草稿。文件需要重新选择。退出登录和失去项目权限会使对应草稿跨标签失效。
- **个人默认视图**：工作台和任务页可保存筛选、排序、分组及列表/看板方式；保存只影响本账号、本浏览器。搜索文本、任务定位、讨论定位不保存为默认视图。
- **私有项目模板**：在项目设置提取阶段、任务、依赖、验收约定与角色占位，编辑后保存至本人模板库。新建入口可选模板；所有新项目角色先明确由创建者承担，创建后再邀请伙伴。向现有空项目应用时，逐一映射当前有效成员。预览不写项目，不复制旧成果、状态、讨论、邀请或账号授权。模板可归档恢复，最多 50 份活跃、100 份含归档历史。
- **有限批量编辑**：最多 50 项有效任务，只改负责人、截止和优先级，先看每项影响。每项核对权限、任务快照与完整最终日程；任一项失败则整批不保存。已完成/取消记录及验收仍逐项处理。
- **AI 三工具**：从项目副驾进入指定区间周报、讨论/纪要行动提取、交付完整性检查。每条事实或候选保留来源引文，点击可定位原任务或讨论。来源只能证明有该记录，不能证明文字或 AI 解读属实；附件正文、链接内容和实际运行结果不在读取范围。周报区分本期已交接与当前快照；行动须逐项编辑并勾选后确认，旧版本拒绝应用；检查不能替代成果接收人验收。
- **模型服务归属**：个人设置可配置自己的 DeepSeek，使用固定官方 HTTPS 接口。凭据以 AES-256-GCM 加密保存在服务器，API 不返回 Key。未使用个人配置时，平台服务需管理员手动开通月额度；新注册账号默认不开通，工作区管理员默认每月 200 次。月份按上海时间，按发起请求尝试计次（含失败），跨项目共享。个人 Key 调用由个人模型账户计费，此版本不处理在线支付或声称已购买服务。

独立 Pages 演示可使用模板、批量和本机草稿/视图，不调用真实模型、不保存个人 Key，也不伪造三个 AI 工具的生成结果。实际 AI 调用请进入正式工作区。

## 本地运行 Pages 演示

需要 Node.js 24 或更新版本，使用 package.json 指定的 pnpm 版本：

```sh
pnpm install --frozen-lockfile
pnpm build:pages
pnpm preview:pages
```

打开终端显示的 `http://127.0.0.1:4173/cobuild/` 进入工作区连接页；本地演示在 `http://127.0.0.1:4173/cobuild/demo.html#/dashboard`。演示沿用原浏览器存储，不自动重置；哈希路由支持任务链接、前进/后退和刷新。端口被占用时可运行 `node scripts/preview-pages.mjs --port 4174`。

`dist-pages/` 是独立静态产物，不要把正式服务端的 public/ 直接作为 Pages 网站发布。静态构建会检查演示适配已经包含，并拒绝混入 server、SQLite 账号和项目存储模块。

## 发布到 GitHub Pages

源码应作为一个独立仓库的根目录，package.json 与 .github/ 在同一级，不要将包含其它项目的父目录一起上传。

1. 将干净源码推送到仓库 main 分支。
2. 在仓库 Settings → Pages 中选择 **GitHub Actions**。
3. Pages 工作流执行测试、安装锁定依赖、静态构建并部署。成功后以工作流输出的页面地址为准。

默认仓库名为 cobuild 时，页面形如 `https://OWNER.github.io/cobuild/`。正式协作仍需部署后端。可在仓库 Actions Variables 中设置公开变量 `COBUILD_SERVICE_URL=https://你的服务地址:端口`，覆盖本仓库工作流已预置的当前线上地址；本地构建未配置时由用户填写。只允许 HTTPS 根地址，入口仅导航，不代理密码、会话或项目数据。模型密钥绝不放入此变量。完整步骤、发布包校验及可选服务器部署见 [GitHub 发布与部署](GitHub发布与部署.md)。

## 运行完整服务端版本

```sh
pnpm build
pnpm start
```

访问 `http://127.0.0.1:4173`，首次使用由本人设置工作区管理员。新安装从零项目、零示例人员开始，设置后只有真实管理员，可直接创建首项目并邀请伙伴。已有项目与旧成员历史保留，管理员是独立的新成员；历史人员通过邀请认领，不按同名自动合并，也不能通过身份切换冒充接收人。

管理员完成首次设置后，其他使用者可在 `/register` 自行创建普通账号。注册后进入自己的空工作区，可创建项目并成为该项目管理员，也可通过邀请加入他人的项目。已绑定账号的伙伴必须接受邀请后获得项目访问；单纯添加档案不会授权账号。普通账号只能访问自己参与的项目；工作区管理员仍可管理与查看工作区中的项目。

首次进入工作区会显示使用指引，介绍创建或受邀加入项目、安排分工与里程碑、提交与验收成果，并按当前项目权限提供入口。可以跳过，也可随时通过右上角菜单的“使用指引”重新查看。跳过或已了解状态保存在当前账号下，跨设备沿用；上线前尚未保存指引状态的已有账号也会提示一次。演示版仅保存当前浏览器的体验状态，重置演示会恢复指引。

想先体验流程时，可从使用指引、空工作台或项目中心打开协作流程示例。示例包含虚拟伙伴、任务、里程碑和示范交付，不创建其他真实账号，也不接受真实成员邀请；真实协作请新建项目。示例可由创建账号删除，并从项目中心恢复，修改内容会保留。每个账号最多一份活跃示例；重复创建会打开已有示例，若已删除则恢复原示例。工作区管理员仍可治理查看工作区项目。普通项目使用独立的归档与恢复入口，归档不删除任务与成果。

注册邮箱忽略首尾空格和大小写，重复时提示“该邮箱已注册”。新注册账号的昵称不能与已注册账号重复，比较时忽略首尾空格、大小写和全半角差异，重复时提示“该昵称已被占用”；账号改名和邀请认领也遵循此规则。历史重名账号和未绑定账号的人员档案保持原样，不自动合并或改名；关联历史档案的邀请使用该档案现有昵称，如已占用需管理员核对档案。

项目管理员、成员和只读权限在服务端执行。成果由指定接收人确认；修改交付约定后需要重新交付和确认。AI 调用由服务端配置，外部接口使用 HTTPS，密钥不返回浏览器。生成草案与查看差异不会写入项目，确认应用检查版本，冲突时保留当前数据。

公开服务需 HTTPS、持久化存储与单写入实例。已提供自包含 Dockerfile、Compose/Caddy 与可选 GHCR 工作流。具体配置、完整备份方式和模型接入见 [部署与配置](部署与配置.md)。邮箱验证与密码找回需配置邮件服务；站内提醒已提供，邀请仍由用户复制链接分享。邮件发送配置与能力限制见部署文档。

## 工程检查

```sh
pnpm test
pnpm build
pnpm build:pages
pnpm doctor
# 在提供公开地址与初始化口令的服务端环境中：
node scripts/doctor.mjs --production
```

模型协议测试只使用本机 fixture，不需要真实密钥。doctor 只读检查运行时、构建资源、存储写入权限和服务配置，不初始化数据库，不联网调用模型，也不保证真实模型余额和能力。

发布脚本按白名单生成可校验的独立发布包，不包含 .local、数据库、上传文件、.env、.secrets、截图或父目录其它应用。安全边界见 [SECURITY.md](SECURITY.md)，本轮变化见 [CHANGELOG.md](CHANGELOG.md)。

## 成员与任务生命周期

成员的“负责方向”和“访问权限”分开维护。移除、退出及降为只读前，未结束任务中的负责人和接收人必须移交；已完成和已取消任务不强制改写。转交管理权会让接任者成为项目管理员，原管理员保留协作者身份及原有任务。管理权只能交给本项目内已经关联真实账号的有效成员。移除或降权会撤销相关待接受邀请，避免旧链接重新取得权限。

离开成员作为历史记录保留，不占当前有效人数，不再可被分派新工作或提及。平台工作区管理员仍为受信任的治理角色，明确离开项目后保留治理查看与成员管理，但不会自动重新加入或获得普通任务写入权限。已有项目中的平台管理员迁移保持兼容。

已取消任务在项目任务页的取消筛选中查看，默认日常工作只显示有效任务；其前置或后续依赖需要管理者明确核对，系统不会因为取消而判定依赖已完成。已确认交接的任务不能取消。恢复时原成员若已离开，需重新指定有效协作者；换人且保留已有成果时需要重新提交，历史版本不会删除。

讨论目前支持纯文本、回复、提及和问题解决，单条最多4000字、单任务最多200条、单项目最多1000条。只读成员可查看但不能发表。提及仅限当前有效成员，不会给陌生账号发送消息。站内提醒保存在账号下，当前未配置外部邮件通知。演示版只有一个本地体验身份，其余预置人物为人员档案；真实管理权交接和邀请需在正式工作区使用真实账号。
